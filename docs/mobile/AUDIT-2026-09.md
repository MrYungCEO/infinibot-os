## 2. What broke with the HTTP auth gate (OSS W2)

The gateway now requires its credential on every HTTP route and on the WS handshake (no loopback trust).

1. **`useGateway.initializePersistence()` called `clearAuthData()` on every launch.** It deleted the saved
   gateway secret each time the app started (a leftover from a hard-coded default password). After that:
   - the WS `connect` frame went out with no `auth` → rejected;
   - `getGatewayAuthHeaders()` returned `{}` → every HTTP call (voice STT/TTS, push-token register,
     hardware, plugin assets) got **401**.
2. **`App.checkExistingAuth()` always set `isAuthenticated = true`**, so the Auth screen was never shown. A
   fresh install could not enter a gateway URL or password at all (URL default is empty since the
   `:47913` fix).
3. WS auth was always sent as `{ password }`. A gateway in token mode (`gateway.auth.mode = token`) needs
   `auth.token`.
4. `GlassesScreen` built its own `Bearer ${token}` from the stored secret, so it would be wrong for cloud.
5. Cloud (SaaS) had no path: no Clerk, no `/fleet/resolve`, no fresh-token-per-request.

Fixed: connection profiles (`mobile/src/connection/*`). There is no more credential wipe. Chooser: Cloud or
self-hosted, pairing QR, probe before save. Token vs password mode. `getGatewayAuthHeaders()` and the WS auth
both come from the active profile (cloud → fresh Clerk JWT per call). Legacy installs migrate automatically.

## 3. Push notifications and deep links (before)

- `app.json` had **no `scheme`**, and there was **no `Linking` handler**. `infinibot://…` links could not
  open the app, and nothing routed them.
- Three separate prefix routers disagreed:
  - `App.handleNotificationTapped` knew 4 prefixes.
  - `NotificationBanner.handleTap` knew 6, mixing `mobile://` and `infinibot://`.
  - `NotificationDetailScreen.parseDeepLink` knew 5 path names, and 2 of them pointed at routes that don't
    exist (`Terminals`, `Sessions`).
- **Double tap handling:** `App` registered `addNotificationTapHandler` *and* `useNotifications` registered
  its own response listener. One tap caused two navigations.
- `navigation.navigate('Chat' | 'Board' | 'Discipline')` from the root stack targets screens nested in
  `MainTabs`. That isn't routable in React Navigation 7, and `Discipline` isn't a route at all.
- **Cold start:** a tap on a push that launched the app was lost, because `getLastNotificationResponseAsync`
  was never read.
- Server side (from the alert research):
  - Pushes carry `data.deepLink` for agent lifecycle, chat, kanban and Discipline, but with 3 dialects
    (`infinibot://…`, `mobile://chat?sessionKey=`, and relative web paths for Infinitrade and Solatrix).
  - Verification verdicts, approvals, goal runs and scheduled-task approvals were **Telegram-only**: no
    push and no link.
  - Telegram messages carried no link at all (`buildInlineKeyboard` dropped URL buttons).
- The mobile `ProactiveOverlayHost.js` is **not on this branch**. It's an untracked file in the owner's
  main tree. On the branch, the proactive feed only showed drift signals, and taps did nothing.
- Push token registration (`/api/push-tokens/register`) was 401 because of 2.1.

Now:
- One grammar (`docs/mobile/DEEP-LINKS.md`) and one resolver (`mobile/src/navigation/deep-links.js`).
- One dispatcher that every surface uses (OS link cold/warm, push cold/warm, banner, detail screen,
  proactive rows).
- Scheme `infinibot` plus App Link `https://<cloud>/m/…` in the manifest.
- Server links: see the server section of RESULT.

## 4. Web Setup › Mobile page

- The page said "Try in Expo Go … no installs", but **Expo Go cannot run this app** (LiveKit / WebRTC /
  expo-dev-client native modules). It needs a dev-client build or an APK.
- It offered no APK. The "Build" tab was iOS-IPA-centric.

Fixed: Android APK card (version, date, size, SHA-256, authed download, QR with a short-lived signed link over
LAN/Tailscale, install steps), plus corrected copy.

## 5. Kept working (regression surface)

- Voice call host (ActiveCallHost / VoiceCallScreen) — untouched except auth headers now valid.
- Content Studio, Grid, Terminals, Agency world map, Discipline native screens — untouched; still reachable
  (via plugin sections when plugins are known, static entries while offline).
- Existing jest suite: 184 tests before → 189 after this branch's first pass (plus the new suites), all pass.

## Left / not done

- Control bar / clock / plugin topbar slots are not ported natively.
- Native screens for Infinitrade, Solatrix and the other new plugins are WebSurfaces, not hand-built native
  screens.
- **Cloud WebSurfaces:** the embedded web UI gets the Clerk token at load time. After ~60 s, its own
  reconnects need a reload. It also assumes the tenant gateway serves the control UI.
- **App Links on `infinibot-cloud.netlify.app`:** you need to publish `/.well-known/assetlinks.json` (package
  plus signing-cert SHA-256) and `apple-app-site-association` on the Netlify site. That is a deploy, so it was
  left to you. Until then, the `/m/` opener page on each gateway performs the hand-off.
